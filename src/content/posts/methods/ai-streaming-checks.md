机场介绍里常见“支持 ChatGPT”“解锁 Netflix”这类说法。对用户来说，真正关心的是：用这个节点，我能不能完成想做的事。这篇文章把“支持”拆成可检查的具体操作，说明每一步该记录什么，以及哪些结论不能从测试里推出来。

## “能打开”不等于“能用”

以视频网站为例，从打开到看完一部剧，至少有几个不同的环节：

1. **网页能打开**：首页加载成功。
2. **能登录**：账号登录不报错。
3. **能看到对应地区的内容**：片库显示的是节点所在地区的内容。
4. **能播放**：指定内容可以开始播放，不提示地区限制。
5. **播放质量**：能达到预期清晰度，不频繁缓冲。

任何一步都可能失败。只测了第 1 步就写“支持”，是最常见的误导。AI 工具同理：页面能打开、能登录、能完成一次对话、能使用需要的功能，是几个不同的检查项。

## 检查项与记录方式

| 服务类型 | 检查项 | 记录什么 |
|---|---|---|
| AI 对话工具 | 打开页面 | 是否成功，是否出现地区提示 |
| | 登录 | 是否成功 |
| | 完成一次对话 | 发送一条固定测试问题，是否得到回复 |
| | 特定功能 | 如文件上传、语音等，逐项记录 |
| 视频网站 | 打开首页 | 是否成功 |
| | 播放指定内容 | 记录内容名称、是否出现地区限制提示 |
| | 清晰度 | 播放器显示的实际清晰度 |
| 短视频 / 社交 | 打开、浏览、发布 | 按需逐项记录 |

每一项都写“成功 / 失败 / 未测”，失败时记录页面上的提示文字（截图时遮挡账号信息）。

## 为什么必须指定节点

同一家机场的不同节点，出口 IP 可能来自不同地区、不同类型的机房。某个服务可能在“美国 01”可用、在“美国 02”不可用。所以：

- 每条结果都要写节点名称；
- 不写“全部节点支持”，除非真的逐个测过；
- 节点的出口 IP 可能变化，结果也只对测试那天有效。

## 网络连通与账号地区资格是两回事

这一点经常被混淆。代理只决定你的网络请求从哪里发出，但服务方是否给你提供服务，还取决于：

- 账号注册地区、付款方式所属地区；
- 服务方对 IP 类型（机房 IP、住宅 IP）的判断；
- 服务方自己的地区政策调整。

所以即使测试显示“节点可以打开并登录”，也**不代表**你的账号在这个节点上一定可用；反过来，失败也可能是账号原因而非节点原因。测试记录里应当注明使用的是什么类型的测试账号。

## 宣传说法怎么读

本站把关于 AI 和流媒体的信息分成三类，在品牌页上分开标注：

- **服务商宣称**：机场自己页面上的说法；
- **资料提及**：服务商介绍或公开资料中的描述；
- **本站测试**：按本文方法实际操作过、有记录的结果。

目前本站品牌页上的相关信息都属于前两类，页面上标注为“资料中提到”，尚未经过本站测试。

## 一次检查的记录格式

下面是填写格式，方括号内为需要替换的内容，不是本站的测试结果：

> 【日期 时间】，【城市 运营商 接入方式】，【设备与系统】，节点“【节点名称】”。AI 对话工具：页面打开【成功/失败】，登录【成功/失败】，发送测试问题后【是否回复】；文件上传【成功/失败/未测】。视频网站：首页打开【成功/失败】，指定内容【可播放/提示地区限制】，播放器显示【清晰度】，【时长】内缓冲【次数】次。结果仅对该节点、该时段有效；使用的是【测试账号类型】。

这类记录的格式和其他测试一致，完整字段见[怎样记录一次可复核的节点测速](/methods/record-node-speed-test/)。

## 常见疑问

### 用“解锁检测”脚本测出来的结果算数吗？

检测脚本通常是访问特定地址、根据返回内容判断，能快速给出参考，但它检测的条件不一定和你的实际使用一致。本站把脚本结果和实际操作结果分开记录，以实际操作为准。

### 今天能用，明天不能用，是机场的问题吗？

不一定。服务方可能调整策略，节点的出口 IP 也可能更换。这也是本站只把结果写成“某日某节点”的原因。

### AI 工具提示地区不支持怎么办？

先换同地区的其他节点试试；如果多个节点都不行，可能和账号本身有关。不要为了绕过限制去使用来路不明的共享账号。

## 小结

检查 AI 和流媒体时：**拆成具体操作、指定节点、逐项记录、区分网络与账号**。没有这样的记录时，“支持”只能当作参考说法。地区和运营商对结果的影响，见[节点地区、运营商与本地网络为什么影响结果](/routes/node-region-isp/)。

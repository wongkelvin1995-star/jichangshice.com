偶尔问 AI 几个问题，只要能打开就行；但如果每天用 AI 写作、编程、分析文件，网络问题会直接影响效率：长回复中途断开、图片上传失败、API 调用超时。这篇文章给出一套一周内能完成的测试方案，帮你判断一个节点是否适合深度使用 AI。

## 测试前准备

1. **选 2–3 个候选节点**：都在你要用的 AI 平台的支持地区内（以平台官方支持地区为准），例如日本、新加坡、美国各一个；
2. **固定客户端和规则**：AI 相关域名分到一个策略组，测试时组内只放当前测试的节点；
3. **准备测试材料**：一段固定的长提示词、一张 2–5MB 的图片、一份 PDF；
4. **准备记录表**：日期、时间、节点、测试项、结果、耗时、备注。

## 五项测试

### 1. 登录

- **测法**：退出账号后重新登录；
- **记录**：是否成功、是否出现人机验证、是否要求额外验证；
- **合格**：一次登录成功，没有反复验证。

### 2. 长对话

- **测法**：发送固定的长提示词，要求输出 1500 字以上的内容；记录从发送到第一个字出现的时间（首字时间），以及是否完整输出；
- **再测**：在同一对话中连续追问 5 次；
- **合格**：首字时间稳定，没有中途断开或“网络错误”。

首字时间受模型和平台负载影响，比较节点时要在相近时间、用同一个模型测。

### 3. 图片与文件上传

- **测法**：上传准备好的图片和 PDF，并让 AI 描述或总结内容；
- **记录**：上传耗时、是否失败；
- **合格**：上传成功，AI 能读取内容。

上传失败而文字对话正常时，常见原因是上传使用了单独的域名没有被分流，或节点上传带宽太低。

### 4. 语音（如果需要）

- **测法**：使用语音对话功能 2–3 分钟；
- **记录**：是否断续、延迟是否明显；
- **合格**：连续对话不断开。语音对延迟和稳定性要求最高。

### 5. API 连通性（开发者）

- **测法**：在终端设置代理环境变量（如 `HTTPS_PROXY=http://127.0.0.1:端口`），用最简单的请求调用一次 API；
- **记录**：是否返回正常结果、耗时、错误类型；
- **合格**：连续 10 次调用不超时、不报地区错误。

注意：命令行工具不一定读取系统代理，需要设置环境变量或开启 TUN 模式。

## 测试节奏

| 时间 | 测什么 |
|---|---|
| 第 1 天白天 | 五项全测，建立基线 |
| 第 1–7 天每晚 21:00 | 长对话和上传 |
| 第 3、6 天 | 重新登录一次 |
| 每天 | 正常使用，记录遇到的错误 |

一周后，看晚高峰时长对话是否经常中断、上传是否经常失败。两个节点都合格时，选首字时间更稳定的那个，长期固定使用。

## 结果怎么判断

一周后，按下面的标准给每个节点打勾：

| 项目 | 合格标准 |
|---|---|
| 登录 | 7 天内重新登录 2 次，均一次成功 |
| 长对话 | 晚高峰中断不超过 1 次 |
| 上传 | 图片和 PDF 均成功 |
| 语音（可选） | 3 分钟内不断开 |
| API（可选） | 10 次调用全部成功 |

全部合格的节点，可以作为长期主力；部分合格的，作为备用；经常失败的，直接排除。

## 常见失败原因对照

- **长回复中途断开**：节点不稳定或晚高峰拥堵，换同地区其他节点对比；
- **上传失败、对话正常**：上传域名没有被分流到代理，或节点上传带宽不足；
- **频繁人机验证**：节点 IP 被大量用户共用，换节点或换地区；
- **API 超时、网页正常**：终端没有走代理；
- **提示地区不支持**：出口地区不在平台支持范围内，见 [ChatGPT 能用但 Claude 不可用的排查](/ai/chatgpt-ok-claude-blocked/)。

## 不泄露账号信息

- 截图时遮挡邮箱、头像、对话中的个人信息和 API 密钥；
- 不要把 API 密钥写进公开的代码或截图；
- 测试记录里只写节点名和结果，不写账号；
- 分享给他人或客服时，只提供节点名、时间和错误信息。

## 常见疑问

### 测一次就够了吗？

不够。至少覆盖一周的晚高峰，AI 平台和网络状态都会变化。

### 首字时间多少算正常？

没有统一标准，受模型和平台负载影响很大。比较节点时，在同一时间、同一模型下对比更有意义。

### API 调用超时但网页正常？

多数是终端没有走代理。设置环境变量或开启 TUN 模式后再试。

### 测试会不会影响账号？

正常使用不会。避免在短时间内频繁切换不同国家的节点登录同一账号。

# Google Search Console 索引问题排查清单

适用于 jichangshice.com.cn 上线后。按顺序检查；每一步都写明“正常应该看到什么”。

## 一、上线当天

1. **网域资源验证**：GSC 添加“网域”资源 `jichangshice.com.cn`，在 Cloudflare DNS 加 TXT 记录。验证通过后，http / https / www 都归在同一资源下。
2. **提交站点地图**：「站点地图」提交 `sitemap-index.xml`。正常：状态“成功”，发现的网址约 103 个（以构建时 `dist/sitemap-0.xml` 的条数为准）。
3. **网址检查首页**：输入 `https://jichangshice.com.cn/` →「测试实际网址」。正常：可以编入索引；用户声明的规范网址 = 当前网址；页面截图能看到首屏和精选机场。
4. **再检查 5 个代表页**并“请求编入索引”：
   - `/airports/`、`/compare/`、`/coupons/`、`/test-records/`
   - `/methods/airport-testing-guide/`（原首页长文，已独立成文章）
5. **确认 noindex 页面不在站点地图里**：`/search/`、`/user/`、`/test-records/submit/`、`/404`。这些页面在“网页”报告里显示“已被‘noindex’标记排除”属于正常。

## 二、上线后 3–14 天：「网页」报告逐项排查

| 报告里的原因 | 本站可能的情况 | 怎么处理 |
|---|---|---|
| 已发现 - 尚未编入索引 | 新站正常现象，Google 还没来得及抓取 | 等待；对重要页面用网址检查“请求编入索引”，每天不要超过 10 个 |
| 已抓取 - 尚未编入索引 | 页面内容与其他页面相似或较薄 | 看是否是品牌测速记录页（内容以表格为主）；补充正文说明或减少相似页面，不要批量生成相似文章 |
| 重复网页，用户未选定规范网页 | 带/不带结尾斜杠、http/https、www 混用 | 确认 Cloudflare 已把 www 301 到主域；站内链接统一带结尾 `/`；canonical 均指向自身 |
| 备用网页（有适当的规范标记） | 例如 `/compare/?brand=xxx` 带参数的网址 | 正常，无需处理 |
| 已被‘noindex’标记排除 | /search/、/user/、/test-records/submit/、/404 | 正常；如果出现其他页面，说明误加了 noindex，需检查 Layout 的 `noindex` 参数 |
| 未找到 (404) | 外部旧链接或改过的网址 | 本站未改动已有路由；如有旧网址，在 Cloudflare 加 301 规则指向新网址 |
| 软 404 | 内容很少的页面 | 检查该页正文是否为空或只有模板文字 |
| 服务器错误 (5xx) / 重定向错误 | 托管或 DNS 问题 | 检查 Cloudflare Pages 部署状态与自定义域设置 |
| 被 robots.txt 屏蔽 | 不应出现 | `robots.txt` 为 `Allow: /`；出现时检查 Cloudflare 是否开启了其他屏蔽规则 |

## 三、其他报告

- **体验 → 核心网页指标**：数据需要足够访问量才会出现；如标红，先看移动端 LCP（首屏插画只在桌面显示，移动端不加载大图）。
- **增强功能 → 面包屑**：品牌页、文章页、测试档案页都输出 BreadcrumbList；出现“无效项”时用网址检查查看具体字段。
- **手动操作 / 安全问题**：应为“未检测到问题”。

## 四、日常维护

- 发布新文章后，sitemap 会在下次构建时自动更新（lastmod 取文章的 pubDatetime / modDatetime），无需重新提交，可对新文章单独“请求编入索引”。
- **日期必须真实**：只有实质修改才填写 `modDatetime`，不要为了“刷新”统一改日期。
- 每月看一次“效果”报告：同一个查询词如果有多个本站页面轮流出现，说明搜索意图重叠，应合并或调整其中一页的标题与重点。
- 不要购买外链、批量生成相似文章或堆砌关键词。
